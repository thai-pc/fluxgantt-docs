# React

`@fluxgantt/react` wraps the engine in a real component and hook. This is the code from
[`examples/react-vite-demo`](https://github.com/thai-pc/fluxgantt/tree/master/examples/react-vite-demo).

## `<FluxGantt>`

```tsx
import { FluxGantt } from '@fluxgantt/react';
import { toTaskId } from '@fluxgantt/core';
import type { TaskInput, DependencyInput } from '@fluxgantt/core';

// Declare data at MODULE scope — see "Uncontrolled data" below.
const tasks: TaskInput[] = [
  { id: toTaskId('design'), name: 'Design', start: '2026-08-03', end: '2026-08-05', progress: 1, type: 'task' },
  { id: toTaskId('build'), name: 'Build', start: '2026-08-05', end: '2026-08-10', progress: 0.6, type: 'task' },
  { id: toTaskId('review'), name: 'Review', start: '2026-08-10', end: '2026-08-12', progress: 0, type: 'task' },
];

const dependencies: DependencyInput[] = [
  { from: toTaskId('design'), to: toTaskId('build'), type: 'FS' },
  { from: toTaskId('build'), to: toTaskId('review'), type: 'FS' },
];

export function App() {
  return (
    <FluxGantt
      tasks={tasks}
      dependencies={dependencies}
      style={{ height: 420 }}
      onTaskMoved={(task, prevStart) => console.log(`${task.name} moved from ${prevStart}`)}
    />
  );
}
```

## Props

`FluxGanttProps` is the engine's `GanttConfig` plus per-event callbacks and standard DOM props:

| Prop | Type | Notes |
|---|---|---|
| `tasks` | `TaskInput[]` | Initial tasks (uncontrolled — read once). |
| `dependencies` | `DependencyInput[]` | Initial dependencies (uncontrolled). |
| `calendar` | `WorkingCalendar` | Construction-time only. |
| `viewMode` | `'day' \| 'week' \| 'month' \| 'quarter' \| 'year'` | Construction-time only. |
| `density` | `'compact' \| 'default' \| 'comfortable'` | Construction-time only. |
| `locale` | `string` | Construction-time only. |
| `rtl` | `boolean` | Mirror the chart for right-to-left locales (the wrapper composes `withRtl`). Construction-time only; change `key` to switch. See [Right-to-left charts](/docs/rtl). |
| `ariaLabel` | `string` | Accessible name of the chart. Construction-time only. |
| `messages` | `GanttMessages` | Accessible-name builders — see [i18n](/docs/i18n). Construction-time only. |
| `readOnly` | `boolean` | Disables drag wiring. |
| `enableDependencyDrag` | `boolean` | Enables drag-to-link dependency handles. Construction-time only. |
| `schedulingMode` | `'manual' \| 'auto'` | `'auto'` cascades dependents. Construction-time only. |
| `canvasViewportHeight` | `number` | Canvas mode only. Construction-time only. |
| `historyLimit` | `number` | Undo entries retained; `0` disables undo. Construction-time only. |
| `initialCollapsed` | `TaskId[]` | Tasks to start collapsed. Construction-time only. |
| `rollup` | `RollupProvider` | Pass `computeRollup` from `@fluxgantt/core`. Construction-time only. |
| `theme` | `'light' \| 'dark' \| 'auto'` | **Reactive** (applied via `setTheme`). Defaults to `'light'` here, not core's `'auto'`; pass `"auto"` to follow the OS. |
| `className` / `style` | `string` / `CSSProperties` | Applied to the container `<div>`. |

### Event callbacks

One callback per engine event: `onTaskAdded`, `onTaskMoved`, `onTaskResized`,
`onTaskProgressed`, `onTaskRemoved`, `onDependencyAdded`, `onDependencyRemoved`,
`onCriticalPathComputed`, plus the catch-all `onTaskChange(task, prev)`. These callbacks stay
reactive — you can pass fresh inline arrows every render.

`onTaskUpdated(payload)` is **experimental** (`@beta`): it may change in any minor release (see
[Stability](/docs/stability)). It bridges core's [`task:updated`](/docs/api#taskupdated-experimental)
event and receives its `TaskUpdatedPayload` (`taskId`, `task`, `prev`, `changed`, and `source` for
undo/redo), which `@fluxgantt/react` re-exports. It fires for every field-level change of an
existing task, after `onTaskMoved` / `onTaskResized` / `onTaskProgressed` and after `onTaskChange`,
so use it **instead of** those, not alongside them:

```tsx
import type { TaskUpdatedPayload } from '@fluxgantt/react';

function onTaskUpdated({ taskId, changed, source }: TaskUpdatedPayload) {
  if (source) return; // undo/redo replay
  console.log(`${taskId} changed: ${changed.join(', ')}`);
}

<FluxGantt tasks={tasks} onTaskUpdated={onTaskUpdated} />
```

## Uncontrolled data (important)

Every `GanttConfig` prop except `theme` and `onTaskChange` is **read once**,
when the underlying `GanttInstance` is created. The instance is the source of truth afterward —
there is no prop→store diffing.

Two consequences:

1. **Declare `tasks`/`dependencies` outside the component** (module scope, or `useMemo`/`useState`).
   A fresh array identity every render doesn't update the chart and triggers a dev-only warning
   (stripped from production builds, see [Production builds](#production-builds)).
   Mutate through the instance instead (see the ref below).
2. **To change a construction-time prop** like `viewMode`, force a remount by changing `key`:
   ```tsx
   <FluxGantt key={viewMode} viewMode={viewMode} tasks={tasks} />
   ```

## The imperative handle

`<FluxGantt ref>` exposes the full `GanttInstance`, so you can drive it imperatively:

```tsx
import { useRef } from 'react';
import { FluxGantt } from '@fluxgantt/react';
import type { FluxGanttRef } from '@fluxgantt/react';
import { toTaskId } from '@fluxgantt/core';

function Toolbar() {
  const gantt = useRef<FluxGanttRef>(null);
  return (
    <>
      <button onClick={() => gantt.current?.addTask({
        id: toTaskId('qa'), name: 'QA', start: '2026-08-12', end: '2026-08-13', progress: 0, type: 'task',
      })}>Add task</button>
      <FluxGantt ref={gantt} tasks={tasks} dependencies={dependencies} />
    </>
  );
}
```

## The `useFluxGantt` hook

If you need the container ref and instance directly (to build your own layout), use the hook the
component is built on:

```tsx
import { useFluxGantt } from '@fluxgantt/react';

function Chart() {
  const { ref, instance } = useFluxGantt({ tasks, dependencies });
  // attach `ref` to your container; `instance` is the full GanttInstance.
  return <div ref={ref} style={{ height: 420 }} />;
}
```

## Grid columns and cell editing

:::warning
**Experimental.** The grid entries are `@beta`, like the [core grid](/docs/concepts/grid-columns)
they wrap (since `@fluxgantt/react` 0.6.0). They may change in any minor release.
:::

Two opt-in entries bring the grid to React. A chart that imports neither ships no grid code; the
default `@fluxgantt/react` entry, its props and its types are unchanged.

| Entry | Exports | Composes |
|---|---|---|
| `@fluxgantt/react/grid` | `FluxGanttGrid`, `useFluxGanttGrid` | `<FluxGantt>` + [`withGrid`](/docs/concepts/grid-columns) |
| `@fluxgantt/react/grid-editing` | `FluxGanttGridEditing`, `useFluxGanttGridEditing` | the above + [`withGridEditing`](/docs/interactions/editing-cells), after `withGrid` (`withRtl` stays last) |

Both also re-export the grid types (`GridColumnInput`, `GridOptions`, `ColumnResizedPayload`,
`CellEditor`, and, from `/grid-editing`, `GridEditingOptions`, `CellEditRequestedPayload`, ...).

```tsx
import { useCallback } from 'react';
import { FluxGanttGridEditing, type GridColumnInput } from '@fluxgantt/react/grid-editing';
import type { CellEditRequestedPayload, ColumnResizedPayload } from '@fluxgantt/react/grid-editing';

// The library never persists widths: read them back and pass them as `width`.
const saved = loadWidths(); // Record<string, number>, validated

// Module scope: the column functions keep a stable identity.
const columns: GridColumnInput[] = [
  { id: 'name', ...(saved.name ? { width: saved.name } : {}) },
  { id: 'start' },
  { id: 'end' },
  {
    id: 'owner',
    header: 'Owner',
    value: (task) => (typeof task.meta?.owner === 'string' ? task.meta.owner : ''),
    ...(saved.owner ? { width: saved.owner } : {}),
  },
];

export function Plan() {
  const onColumnResized = useCallback(({ widths }: ColumnResizedPayload) => saveWidths(widths), []);
  const onCellEditRequested = useCallback((e: CellEditRequestedPayload) => {
    if (e.columnId === 'owner') {
      e.preventDefault(); // synchronously: open YOUR editor instead of the built-in one
      openOwnerPicker(e.taskId, e.clientX, e.clientY);
    }
  }, []);
  return (
    <FluxGanttGridEditing
      tasks={tasks}
      gridColumns={columns}
      gridOptions={{ durationUnit: 'days', collapseBelow: 480 }}
      gridEditing={{ isEditable: (task) => task.meta?.locked !== true }}
      onColumnResized={onColumnResized}
      onCellEditRequested={onCellEditRequested}
      style={{ height: 420 }}
    />
  );
}
```

### Props

| Prop | Entry | Notes |
|---|---|---|
| `gridColumns` | both | `readonly GridColumnInput[]`. Read at creation; a later change is applied with `setGridColumns` (see below). Invalid columns throw a `RangeError` (at creation, wrapped in the usual "invalid initial config" error). |
| `gridOptions` | both | `collapseBelow`, `durationUnit`, `resizable` (core's `GridOptions` without `columns`). **Construction-time only.** |
| `onColumnResized` | both | `(payload: ColumnResizedPayload) => void`. Always follows the latest render. |
| `gridEditing` | `/grid-editing` | `isEditable`, `beforeCommit`, `activate`, `commitOnBlur` ([options](/docs/interactions/editing-cells#composition-order)). `activate` and `commitOnBlur` are **construction-time only**. `isEditable` and `beforeCommit` follow the latest render, provided they were set on the first one, so inline arrows are fine there. |
| `onCellEditRequested` | `/grid-editing` | `(payload: CellEditRequestedPayload) => void`. Call `payload.preventDefault()` synchronously to replace the built-in editor. Always follows the latest render. |

Every `<FluxGantt>` prop and callback works as before, and the edit-hook callbacks
(`onTaskActivated`, `onTaskContextRequested`) report `part: 'cell'` and `columnId` on grid cells.
Changing a construction-time option (or adding `isEditable` / `beforeCommit` after the first
render) is ignored and logs **one** dev warning; change `key` to remount.

### The ref

The ref is the full instance, typed `FluxGanttGridRef` / `FluxGanttGridEditingRef`. On top of
`FluxGanttRef` it carries `getGridColumns`, `setGridColumns`, `resizeGridColumn` and
`exportGridCsv`, and with editing `startCellEdit`, `cancelCellEdit` and `isEditingCell`:

```tsx
import { useRef } from 'react';
import { FluxGanttGridEditing, type FluxGanttGridEditingRef } from '@fluxgantt/react/grid-editing';
import { toTaskId } from '@fluxgantt/core';

function Editable() {
  const gantt = useRef<FluxGanttGridEditingRef>(null);
  return (
    <>
      <button onClick={() => gantt.current?.startCellEdit(toTaskId('build'), 'name')}>Rename "Build"</button>
      <button onClick={() => download(gantt.current?.exportGridCsv() ?? '')}>Export grid</button>
      <FluxGanttGridEditing ref={gantt} tasks={tasks} gridColumns={columns} />
    </>
  );
}
```

`useFluxGanttGrid(config)` and `useFluxGanttGridEditing(config)` return `{ ref, instance }`, like
[`useFluxGantt`](#the-usefluxgantt-hook).

### Column changes and widths

- **Columns are compared structurally**: ids, widths, headers, bounds, alignment, and the identity
  of the `value`, `format` and `editor` functions. When they differ, the wrapper calls
  `setGridColumns` (one repaint, **never a remount**). Passing an equal array is a no-op.
- **Keep the function identities stable.** Define columns at module scope, or build them with
  `useMemo` / `useCallback`. An inline `value` arrow is a new function on every render, so the
  columns are re-applied (and the grid repainted) on every render, an open editor is held back, and
  one dev warning is logged per component.
- **User-resized widths survive re-renders.** A re-apply keeps the live width of every column
  whose declared `width` did not change, so re-passing the same columns never resets a user
  resize. To reset widths: change the declared `width`s, call `ref.current.setGridColumns(...)`,
  or change `key`.
- **Persist widths yourself**: save `payload.widths` from `onColumnResized` and pass them back as
  `width` ([recipe](/docs/concepts/grid-columns#persisting-widths)).
- **A re-apply waits while a cell is being edited**, and happens once when the edit ends, so an
  open editor and its text are never lost.

## Production builds

The dev-only warnings (`tasks` / `dependencies` changed identity, a construction-time grid option
changed, unstable column functions) are guarded by a bare `process.env.NODE_ENV !== 'production'`
check, which your bundler replaces (Vite and esbuild `define`, webpack `DefinePlugin`). Since
`@fluxgantt/react` 0.6.0 a production build therefore strips them, text included, from the
default entry as well as the grid entries. Before 0.6.0 the check was written so that a browser
bundle evaluated it as "development" and shipped the warnings. An unbundled load without a
`process` global logs no warnings.

## StrictMode

The wrapper is StrictMode-safe: the instance is created once via lazy ref init and the mount
effect's cleanup calls `instance.unmount()` (never `destroy()`), so React's dev-only double
mount/unmount doesn't tear it down permanently.
