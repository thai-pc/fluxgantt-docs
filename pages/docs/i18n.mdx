# Internationalization

FluxGantt ships **English only**, and will keep doing so — the library bundles no translations
and no catalog format. What it gives you instead is a place to put your own.

There is very little to translate. The chart's visible text is almost entirely your data (task
names, your own column headers) plus dates, and dates already go through `Intl`: set
[`locale`](/docs/api#ganttconfig) and they format themselves in any language the browser knows.

```ts
createGantt({ tasks, locale: 'vi' }); // dates become "5 thg 1, 2026"
```

That leaves a handful of strings the library itself composes, and all of them are for assistive
technology rather than text you see on screen: the chart's name, the per-task sentence, grid
column header names and the live-region announcements.

## The chart's name

```ts
createGantt({ tasks, locale: 'vi', ariaLabel: 'Kế hoạch dự án' });
```

`ariaLabel` names the chart as a whole. It defaults to `'Gantt chart'`, and it is also what
`exportSvg()` / `exportPng()` write into the exported file's `<title>` — so setting it localizes
your exports too.

## The per-task sentence

Each task bar announces something like:

```
Design mockups, Jan 5, 2026–Jan 8, 2026 (50% complete), critical path, selected
```

To say that in another language, supply `messages.taskLabel`. It receives every piece of state
and returns the finished sentence:

```ts
createGantt({
  tasks,
  locale: 'vi',
  messages: {
    taskLabel: ({ name, startLabel, endLabel, progressPct, isCritical, isSelected }) => {
      let s = `${name}, ${startLabel}–${endLabel} (hoàn thành ${progressPct}%)`;
      if (isCritical) s += ', đường găng';
      if (isSelected) s += ', đang chọn';
      return s;
    },
  },
});
```

### Why a whole sentence, not a table of fragments

The obvious design — a `{ criticalPath: 'đường găng', selected: 'đang chọn' }` lookup table —
does not actually work, and FluxGantt deliberately does not offer one.

The English sentence used to be built by *appending*: take the base clause, add `', critical
path'`, then add `', selected'`. Swapping the fragments for translated ones keeps that order and
that punctuation. Plenty of languages cannot accept it — a verb-final language needs the clauses
rearranged, an inflecting one needs the task name's ending to change depending on the clause that
follows it. No fragment table can express either.

So the library hands you all of the state and none of the grammar. You control the order, the
inflection and the punctuation, which is what makes the string genuinely translatable. It also
means FluxGantt bundles no message-format parser at all.

### What you get

| Field | Type | Notes |
|---|---|---|
| `name` | `string` | The task name, truncated to 200 characters. |
| `startLabel` / `endLabel` | `string` | Already formatted with `Intl` for your `locale`. For a summary row these are the **rolled-up** span, matching what the bar is drawn at. |
| `progressPct` | `string` | Whole-number percent, already localized (an `ar-EG` host gets Arabic-Indic digits). The `%` sign is **not** included — its placement varies by locale, so it belongs to your sentence. |
| `isCritical` / `isSelected` | `boolean` | |
| `locale` | `string` | The configured locale, for any extra formatting you do. |

If your function throws or returns a non-string, FluxGantt falls back to the English sentence
rather than breaking the chart. It does so silently: this runs once per task per repaint, so a
warning would print thousands of identical lines in a single paint of a large chart.

## Grid column headers

With [grid columns](/docs/concepts/grid-columns) composed, each column header's text is the
`header` you give the column (the built-ins default to English: "Name", "Start", "End",
"Duration", "Progress"), so translate the headers in `columns`. Start/end dates and durations are
formatted with `Intl` in your `locale`.

A header's **accessible name** defaults to its header text; assistive technology adds the column
position from `aria-colindex`. To change it, supply `messages.gridColumnLabel` (experimental):

```ts
createGantt({
  tasks,
  locale: 'de',
  messages: {
    gridColumnLabel: ({ header, index, count }) => `${header}, Spalte ${index} von ${count}`,
  },
});
```

It receives `{ columnId, header, index, count, locale }` (`index` is 1-based). Throwing or
returning a non-string falls back to the header text.

## Live-region announcements

With [`withInteraction`](/docs/interactions/drag) composed, the chart owns a polite live region and
announces the result of a keyboard action there: a task moved, resized or linked from the
keyboard ([Keyboard alternative to dragging](/docs/interactions/drag#keyboard-alternative-to-dragging)),
and, with [grid columns](/docs/concepts/grid-columns), a column resized from the keyboard. To
translate or reword them, supply `messages.announce` (experimental, `@beta`). It receives a
`GanttAnnouncement`, a union discriminated by `kind`, and returns the text to announce:

| `kind` | When | Fields |
|---|---|---|
| `moved`, `resized`, `cannot-move`, `cannot-resize` | <kbd>Alt</kbd>+Arrow / <kbd>Alt</kbd>+<kbd>Shift</kbd>+Arrow on a task row | `id`, `name`, `start`, `end`, `startLabel`, `endLabel`, `locale` |
| `linked`, `link-failed` | <kbd>Alt</kbd>+<kbd>Enter</kbd> | `fromId`, `toId`, `from`, `to`, `reason?` (`'duplicate'` / `'cycle'` / `'self'`), `locale` |
| `column-resized` | <kbd>Alt</kbd>+<kbd>←</kbd>/<kbd>→</kbd> on a focused grid column header (since core 0.10.0) | `columnId`, `header`, `width` (the resulting width in px, unchanged at a limit), `locale` |

```ts
createGantt({
  tasks,
  locale: 'de',
  messages: {
    announce: (a) => {
      switch (a.kind) {
        case 'moved':
          return `${a.name} verschoben: ${a.startLabel} bis ${a.endLabel}`;
        case 'column-resized':
          return `${a.header}: ${a.width} Pixel breit`;
        // …the other kinds…
        default:
          return 'Geändert'; // a kind this code does not know yet
      }
    },
  },
});
```

- **Keep a `default` branch.** The union is experimental and gains kinds in minor releases
  (`column-resized` arrived in 0.10.0). Code written before a kind existed must still return
  something sensible for it; without a `default` it returns `undefined` at runtime, which falls back
  to the English text.
- Throwing, or returning a non-string, falls back to the English text (`Name: 160 pixels wide` for
  a column).
- Pointer drags are never announced, neither of tasks nor of column dividers. Listen to
  `task:moved` / `task:resized` / `column:resized` if your app wants to.
- Without `withInteraction` there is no live region, so nothing is announced.

## Construction-time only

`locale`, `ariaLabel` and `messages` are all read **once**, when the chart mounts. There is no
`setLocale()` or `setMessages()`. To switch language at runtime, recreate the instance — in React,
change the `key` prop:

```tsx
<FluxGantt key={locale} tasks={tasks} locale={locale} messages={messages[locale]} />
```

## Not yet supported

- **Translated built-in strings.** Core ships English only; the library-composed strings are
  yours to supply through `messages` (above). RTL *geometry* is supported — see
  [Right-to-left charts](/docs/rtl).
- **A different date skeleton.** Dates arrive pre-formatted; you cannot currently ask for a
  different `Intl.DateTimeFormatOptions` per message.
- **Other message keys** — tooltips, empty state. These either localize
  through `Intl` already or have no library-composed text today. `GanttMessages` is an interface of
  optional keys, so adding them later is not a breaking change.
